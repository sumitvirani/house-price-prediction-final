1. Introduction

This project delivers a production-ready House Price Prediction web application built entirely in Python. It combines a scikit-learn machine-learning model with a FastAPI REST backend and a Streamlit interactive frontend. The system is containerised with Docker, deployable on Render (backend) and Streamlit Community Cloud (frontend), and fully tested with 61 automated checks.

The application allows any user to enter block-group characteristics of a Californian neighbourhood and receive an instant median house-price estimate together with a confidence range — all without requiring any paid API, private dataset, or manual model retraining at runtime.

2. Problem Statement

Real-estate valuation is complex, time-consuming, and often opaque. Buyers, sellers, and analysts need a fast, data-driven estimate of median house prices based on measurable neighbourhood features such as income, age, room count, and geography. The challenge is to build an end-to-end system that:

  • Learns from real historical housing data
  • Exposes predictions through a secure, documented API
  • Presents results to non-technical users via an intuitive dashboard
  • Can be deployed to the cloud without expensive infrastructure

The California Housing Dataset is derived from the 1990 U.S. Census. Each row represents one block group — the smallest geographical unit for which the Census Bureau publishes sample data (~600–3,000 people). Prices are originally in units of $100,000; the training script converts them to full dollar values. Houses capped at $500,001 in the raw data are excluded as censored observations.

6. Machine Learning Algorithm

Algorithm: Gradient Boosting Regressor

Gradient Boosting builds an ensemble of shallow decision trees sequentially, where each new tree corrects the residual errors of the previous ensemble. It is well-suited for tabular regression tasks with mixed numerical features.

HyperparameterValueRationale
n_estimators300More trees reduce bias; early overfitting controlled by learning rate
learning_rate0.05Low rate + high estimators = strong generalisation
max_depth5Captures feature interactions without over-fitting
subsample0.8Stochastic gradient boosting reduces variance
min_samples_split5Prevents splits on very small leaves
min_samples_leaf3Smooths decision boundaries

Preprocessing Pipeline

  • Target values capped at $500,001 (remove censored rows)
  • Feature values clipped at 99th percentile (remove extreme outliers)
  • StandardScaler fitted on training set; applied at inference time
  • 80/20 train-test split, random_state=42

8. Backend (FastAPI)

The backend is a FastAPI application served by Uvicorn. It loads all model artifacts (model.pkl, scaler.pkl, feature_info.json, metrics.json) once at startup. If artifacts are missing, the server starts in a degraded state and returns HTTP 503 from model-dependent endpoints instead of crashing.

Key Design Decisions

  • CORS enabled for * — frontend can be hosted anywhere
  • Pydantic v2 field validators enforce domain constraints (e.g. AveBedrms ≤ AveRooms)
  • Predictions clamped to [$50k, $800k] to prevent nonsensical outputs
  • Input echoed back in response so frontend can audit the request
  • PORT env variable used for Render compatibility

Start Command

uvicorn backend.main:app --host 0.0.0.0 --port $PORT

14. Conclusion

This project successfully delivers a complete, production-ready House Price Prediction application. The machine-learning pipeline achieves a Test R² of 0.8288 and a Test MAE of $31,668 on the California Housing dataset, which are competitive results for this benchmark.

The FastAPI backend exposes a clean, versioned REST API with Pydantic input validation, CORS support, and graceful degradation when model artifacts are missing. The Streamlit frontend provides an intuitive four-page dashboard with interactive Plotly charts, a live prediction panel, and a geographic house-price map. The entire stack is containerised and documented for one-command local development or cloud deployment.

61 automated tests covering file existence, model quality, all API endpoints, input validation, and frontend-backend contract all pass without errors.
